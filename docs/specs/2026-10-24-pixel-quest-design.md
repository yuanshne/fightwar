# 《像素勇者 Pixel Quest》游戏设计方案

日期：2026-10-24 ｜ 状态：待 grilling 拷问 → 三子 agent 并行实现

## 1. 定位与成功标准

- **类型**：类马里奥横版闯关平台跳跃游戏，单人，键盘操作。
- **载体**：本地 HTML5（Canvas 2D），双击 `index.html` 即玩（file:// 协议可用），零外部依赖（无 CDN、无字体、无图片/音频文件——素材全部代码生成）。
- **目标玩家体验**：5 分钟上手，30~45 分钟通关；每关引入 1~2 个新机关；死亡惩罚轻（检查点复活）。
- **成功标准（验收）**：
  1. 6 关全部可以被普通玩家通关（机关几何经过实测校验）；
  2. 打开控制台无任何报错，稳定 60fps（Chrome/Edge）；
  3. 所有音效/音乐可开关并持久化；进度（解锁+星级）localStorage 持久化；
  4. 视觉统一为 16px 像素风，6 主题有明显差异。

## 2. 技术架构

- 分辨率：内部分辨率 384×224（24×14 瓦片），CSS 整数倍放大 + `image-rendering:pixelated`。
- 定时：固定时间步长（1/60s 累加器），渲染插值可省略。
- **模块拆分（为三 agent 并行设计）**，四个 `<script>` 顺序加载，通过全局对象通信：

| 文件 | 职责 | 对外暴露（全局） |
|---|---|---|
| `art.js` | 精灵图、调色板、6 套主题、程序化瓦片、视差背景、装饰物、像素字体 | `SPR` `THEMES` `buildArt(theme)` `drawPixelText` `drawCNText` |
| `levels.js` | 关卡构建 DSL（LG 类）+ 6 关数据 + 每关元信息 | `LG` `LEVELS` |
| `engine.js` | 物理、碰撞、全部机关更新逻辑、敌人 AI、死亡/复活、关卡解析（Level 类） | `PHY` `Level` `game` `loadLevel` `updateWorld(dt)` |
| `ui.js` | 渲染全部画面、HUD、标题/选关/暂停/结算界面、输入、音频调度、主循环、存档 | `render()` `boot()` |

- **契约规则**：engine 不 draw，ui 不改物理状态；art 只提供素材与绘制原语；levels 是纯数据。跨模块只读对方暴露的全局。

## 4. 关卡结构（教学曲线）

1. **草原初试**（grass，100×14）：移动/跳跃/金币/史莱姆/弹簧，全程几乎无死亡陷阱。
2. **幽暗洞窟**（cave，110×20，纵向）：尖刺/崩塌桥/蝙蝠/钥匙门，中段检查点。
3. **天空栈道**（sky，120×14）：横移平台/弹簧链/崩塌台阶，坠落即死。
4. **齿轮工厂**（factory，120×18）：拉杆切换/传送带/大炮/横锯，双检查点。
5. **烈焰深渊**（lava，130×16）：熔岩海+弹簧岛链/竖锯，三检查点，难度峰值前最后缓冲。
6. **最终之塔**（tower，44×36，纯纵向登顶）：全部机关综合，双检查点，通关撒花。

- 星级：★通关 / ★金币全收 / ★限时（每关 par 40/70/65/85/95/150s）。
- 难度校验：常规跳跃跨 ≤3 瓦片、爬 ≤2 瓦片高墙；弹簧弹跳 ≈5.5 瓦片高。所有关卡由主 agent 浏览器实测通过后再交付。

## 5. 物理参数（engine.js 常量，可调）

重力 1500、最大下落 360、加速度 1400、摩擦 1800（冰面 180）、最大速度 120、跳跃初速 330（长按渐弱截断）、弹簧 520、土狼时间 0.09s、跳跃缓冲 0.11s。玩家碰撞盒 10×14。

## 6. 美术与音频

- 全部手绘像素（字符串网格→离屏 canvas），主角 12×14（兜帽小勇者，8 动画帧），敌人/物品同规格；瓦片 16×16 程序化生成（草/石/云/金属/玄武岩/紫砖 6 套）。
- 每主题：双色渐变天空 + 2 层视差剪影 + 装饰物（灌木/水晶/齿轮/火把等）+ 专属粒子色。
- 音频：WebAudio 合成 15 个音效 + 双轨循环 BGM（方波主旋律+三角波贝斯），M 键静音，设置持久化。

## 8. 已知风险与既知问题（来自半成品）

1. 旧单文件在弹簧段落有花括号破损（将废弃旧文件、模块化重写，但素材代码可搬运）；
2. L4 第二拉杆段的橙/蓝砖语义需要重设计为"先堵后通"清晰链路；
3. L5 有一处残留的浮空熔岩格；
4. 移动平台与玩家挤压、崩塌砖重生时玩家重叠——需在 engine 中显式处理；
5. file:// 下 localStorage 可用性：Chrome/Edge 均可用，Safari 需提示。

## 9. 非目标（YAGNI）

不做：移动端触屏、双人、地图编辑器、成就系统、Boss 战、多语言。后续可作为 v2 迭代。

| # | 拷问 | 结论/修订 |

| 1 | Flash 轻量模型写碰撞物理靠谱吗？ | 风险最高的是 engine.js。修订：给 C 的规格附**伪代码级算法**（逐轴 AABB 扫描、单向平台 wasFeet 条件、平台载人 dx/dy），禁止自由发挥；主 agent 集成后逐条对照实现 |
