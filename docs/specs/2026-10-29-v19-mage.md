# v19 · 第二角色「星语法师」冻结规格

> 玩家原话：「再构建一个角色，要求偏向法师角色，角色技能应该主要是偏向远程」。
> 本文是**唯一设计基准**。四队并行施工（art / engine / ui / tests），跨文件接口以本文为准；
> 与 CONTRACT 冲突时以本文 + CONTRACT v19 附记为准，其余旧条款一律不动。

## 0. 目标与红线

- 新增可玩角色 **mage / 星语法师**，与现有 **knight / 星旅勇者** 并列，可在标题屏/选关屏切换，持久化。
- 法师四技能 **全部为远程/召唤物输出**（I 为唯一防御技，见 §1.3 说明）。
- **knight 行为逐字不变**：默认 hero='knight'，所有旧存档、旧门禁、旧平衡数值零回归。
- 不改玩家移动物理（PHY 一字不动）：`reach` 门禁的 27 个目标依赖骑士物理，法师共用同一套身体。
- 不新增契约外全局符号，唯一例外：engine.js 新增 `const HEROES`（本文 §1.1，写进 CONTRACT 附记）。
- art 顶层零 DOM；engine 不 draw/不发声/不读键盘；ui 不写世界状态（除既有 `game.hero` 注入）。

### 1.2 BAL 新增 `heroes.mage`（数值唯一真值）

```js
BAL.heroes = {
  mage: {
    hpBase: 4,                 // 玻璃大炮：比勇者少 1 心
    manaMax: 100, manaRegen: 3, manaPerHit: 5, manaPerKill: 12,   // v20.4：regen 5→3 / 命中 8→5
    bolt: { cd:0.46, dmg:2, v:300, life:0.60, w:8, h:6, homeR:85, homeDeg:26, turn:4 },   // v20.4：cd 0.38→0.46 / life 0.85→0.70（射程 255→210）；v20.6：追踪 110→85 / turn 6→4；v20.7：life 0.70→0.60（射程 180）
    u: { cd:6,  mana:30, dmg:3, v:420, life:0.9,  pierce:3, w:16, h:6 },
    i: { cd:10, mana:25, dur:2.5, absorb:2 },                    // 复用骑士护盾实现，只换参数
    o: { cd:20, mana:0,  t:[0.35,0.90,1.20], n:6, dmg:2, aoe:30, fallV:340, gap:0.08 },   // v20.6：dmg 3→2（大招 Boss 总伤 18→12）
    l: { cd:6,  mana:25, n:3,  dmg:2, v:230, life:1.6, turn:5, homeR:260 }
  }
};
```

设计意图（写进注释，供后续调参；v20.4 用户实测「法师太强」后四连削）：
- 普攻 DPS≈2/0.46≈4.3，低于骑士 5.7；攻速 0.38→0.46、射程 255→210→180px（life 0.85→0.70→0.60×300，v20.7 再砍一刀），
  换来的安全性由「少 1 心 + 法力门槛」支付。
- 法力循环：满 100；每秒回 3；普攻命中 +5；击杀 +12。U+L 一轮 55 法力 ⇒ 需要约 18 秒自然回蓝，
  且命中回蓝不再是「5 秒回满」（v20.4 前连中 13 发≈5s 回满 100 蓝 = 相当于没有限制），
  **鼓励持续命中而不是站桩丢技能**。
- O 不耗蓝，是唯一的爆发出口：6×3=18 点 Boss 伤害（骑士大招 5 点 + 全屏清怪），
  但法师大招不清弹幕、不秒杀小怪，只提供伤害。

## 2. engine.js 契约

### 2.1 新增字段（沿 v2/v3「扩展字段」先例，不新增第二份状态机）

`game`：
- `hero: 'knight'` —— 由 ui 在 `loadLevel` **之前**写入；engine 内 `_engHero()` 回落 knight。
- `mana: 0`、`manaMax: 0`、`manaToast: 0`。
- `shots: []` —— 法师远程弹体（**不要复用 `game.bullets`**：后者全部按「敌方」结算伤害）。

玩家：
- `shotSeq: 0` —— 法师普攻的「一次起手只发一发」序号（对标 `atkSeq`）。
- `mana` 不挂在玩家上，统一用 `game.mana`（HUD/复活/换关只认一处）。

### 2.2 初始化 / 复位

- `loadLevel`：`const H=_engHero();` → `game.manaMax = H.usesMana ? BAL.heroes.mage.manaMax : 0;`
  `game.mana = game.manaMax; game.manaToast = 0; game.shots = [];`
  新玩家 `maxHp = H.hpBase + equip.hp`。
- `respawn`：`game.mana = game.manaMax; game.manaToast = 0; game.shots.length = 0;`
  `p.shotSeq = 0; p.maxHp = _engHero().hpBase + equip.hp;`
- `killPlayer` / 死亡：清 `p.shotSeq`，其余同现有。

### 2.3 普攻（`_engResolveAttack` 首行分流）

```js
function _engResolveAttack(L,p){
  if (game.hero === 'mage') { _engResolveMageAttack(L,p); return; }
  ... 骑士原逻辑一字不动 ...
}
```

`_engResolveMageAttack`：
- `if (!(p.atkT > 0) || p.dead || p.shotSeq === p.atkSeq) return;`
- 起手时已在 §2.4 设好 `p.atkSeq++`；这里发一发 `game.shots.push(...)`，然后 `p.shotSeq = p.atkSeq`。
- 弹体：`{kind:'bolt', x:p.x+p.w/2-4+p.face*8, y:p.y+5, w:8,h:6, vx:p.face*300, vy:0,
  life:0.60, dmg, crit, pierce:0, hitList:[], homeR:85, homeDeg:26, turn:4, face:p.face}`。
- `p.castT = Math.max(p.castT, 0.12)`（施法姿态）；`game.sfxQueue.push('bolt')`；
- 弹体追踪参数（v20.6：homeR 110→85、turn 6→4——「几乎必中」的微追踪收紧，命中率/回蓝/实际 DPS 同步降）。
  枪口 4 粒青白粒子（`_engAddParts(...,'#8ae8ff',...)`）。
- 伤害口径与骑士一致：`ATK = BAL.player.atkBase + equip.atk`；`crit = ((game.combo+1)%4)===0`；
  `dmg = crit ? ATK*2 : ATK`。
- 不产生近战判定框、不触发 `renderSlash`。

### 2.4 攻击起手（`_engUpdatePlayer` 起手块）

```js
p.atkCd = H.usesMana ? BAL.heroes.mage.bolt.cd : _engAtkCd;
p.atkAnim = _engAtkAnim; p.atkWind = _engAtkWind; p.atkT = 0;
p.atkSeq = (p.atkSeq || 0) + 1;
```
其余不变。攻击窗口仍 0.05s 起手 + 0.12s 判定。

### 2.5 技能（`_engUpdateSkills` 按 hero 分流）

knight 原四条分支**逐字保留**。mage 分支：

- 统一入口 `_engCastMana(cost)`：法力足够 → 扣、返回 true；不足 → `game.manaToast=0.9`、
  `game.sfxQueue.push('nomana')`（仅当 toast≤0 时推，防连按刷音）、返回 false。
- **U**：`if(S.u<=0 && !p.dead && _engCastMana(30))` → `S.u=6*cdMul; p.castT=0.3;`
  push 一枚 `kind:'lance'` 弹体（穿透 3；`hitList:[]`），sfx `'lance'`，冰蓝粒子。
- **I**：`if(S.i<=0 && !p.dead && _engCastMana(25))` → `S.i=10*cdMul; p.shieldT=2.5; p.shieldHp=2;`
  sfx `'shield'` + 现有 12 粒金粒子（可改青色 `'#8ae8ff'`）。
- **O**：`if(S.o<=0 && game.ultCharge>=100 && !p.dead)` →
  `S.o=20*cdMul; game.ultCharge=0; game.ult={on:true,t:0,fired:false,flashed:false,kind:'mage'};`
  sfx `'ult'`。**不耗蓝**。
- **L**：`if(S.l<=0 && !p.dead && _engCastMana(25))` → `S.l=6*cdMul; p.castT=0.3;`
  连推 3 枚 `kind:'seek'` 弹体（v=230、life=1.6、turn=5、homeR=260、dmg=2、
  y 依次 `p.y+4 / p.y+7 / p.y+10`，vx 同向），sfx `'seek'`。

### 2.6 `game.shots` 步进（`_engUpdateShots(dt)`）

- 调用点：`updateWorld` 的 **⑨⁗ blades 之后、⑩玩家之前**（与星刃同层；hitStop/ult 冻结语义自动继承）。
- 每发：`life-=dt`；追踪（若 `homeR>0` 且场上有目标）先转向再位移；越界/超时删除。
- 碰撞优先级：**Boss → 波 → hazards(clone/mirror/core/totem) → 敌人 → 敌弹 → 瓦片 → 装饰**。
- 伤害：
  - Boss：`_engBossHurt(s.dmg, s.isUlt)`，命中后 `_engAddCombo()`×2、`_engFloat(...b.lastDmg...)`、
    `game.hitStop=_engHitStop`、sfx `'hit'`；`s.pierce--`，归零删除。
  - 敌人：同骑士攻击分支（`e.hitSeq` 不适用——用 `s.hitList.indexOf(e)` 防重复）；存活给
    `e.kb = face*_engKbV*(elite?BAL.elite.kbMul:1)`、`flashT/jitT`；死亡走 `_engKillEnemy(e)` +
    击飞弹道；暴击金色浮字。每命中 `_engAddCombo()` + 回蓝 `game.mana += 5`（**只对 bolt 与 seek**，
    长矛不回蓝，防穿透回满）。
  - hazards：totem/mirror 扣 1 血（同骑士口径），core 走 `_engCoreHit(hzArr,hz,1)`，
    clone 扣 `s.dmg` 并 `_engAddCombo()`；不要在此结算爆炸/破盾（收尸分别在 `_engUpdateHazards`）。
  - 敌弹：销毁双方 + 火星粒子（同骑士斩弹）。
  - 瓦片：`'#'/'I'` 停止；`'B'` 碎 +金币 + combo；`'G'` 碎 + combo；`'(' / ')'` 视为实心（同 `solid`）。
  - 装饰：`_ENG_DECOR_HIT[type].cls==='break'` 且重叠 → 同骑士结算（+1 金币、comb +1）。
- 穿透：`s.pierce>0` 时不因命中敌人删除，只扣 `pierce`；撞墙/撞 Boss 仍删除。
- 清理：倒序 `splice(i,1)`；`respawn/loadLevel` 整组清空。
- 性能：`shots` 上限 32（超出丢最旧），符合 `BAL.guard` 精神。

### 2.7 大招状态机（复用唯一 `game.ult`，按 `u.kind` 分支）

- `u.kind==='mage'` 时：
  - `t<0.35`：世界冻结（return），玩家无敌（`p.invT=Math.max(p.invT,0.35)`）——吟唱。
  - `t>=0.35` 一次性：按本屏 `[cam.x+32, cam.x+352]` 均匀生成 6 颗陨星：
    `game.meteors.push({x, y:game.cam.y-24, vy:340, w:10, h:12, delay:i*0.08,
      ring:_engGroundY(x,game.cam.y), dmg:3, bossDmg:3, aoe:30, mage:true})`；
    `game.sfxQueue.push('storm')`；`_engShake(5,0)`。
  - `t>=0.90` 白闪；`t>=1.20` 复位。0.35~1.20 期间**世界正常推进**（不 return）。
- 陨星更新（§⑨″）把 `BAL.skills.u.dmg/bossDmg/aoe` 改为
  `m.dmg || BAL.skills.u.dmg` / `m.bossDmg || BAL.skills.u.bossDmg` / `m.aoe || BAL.skills.u.aoe`；
  knight 的陨星不带这些字段 ⇒ 行为逐字不变。
- 法师陨星视觉：`m.mage=true`（ui 画青紫色流星）。

### 2.8 资源与杂项

- 法力回复：`_engUpdatePlayer` 内，mage 且 !dead 时 `game.mana = min(manaMax, mana+3*dt)`（v20.4：5→3）；
  `game.manaToast = max(0, manaToast-dt)`。
- 击杀回蓝放在 `_engKillEnemy` 内（仅 mage）：`game.mana += 12`（clamp）。
- `_engHero()` 内部函数：`return HEROES[game.hero] || HEROES.knight;`。
- 新 sfx 事件：`'bolt','lance','seek','storm','nomana'`（只 push，ui 消费）。
- **禁止**新增第二个 `_engUpdatePlayer` / 第二个 ult 对象 / 第二个普攻时间轴。

## 3. ui.js 契约

### 3.1 选角状态

- `progress.hero`：`'knight'|'mage'`，缺省/非法回落 `'knight'`；`migrateProgress` 只增键。
- 选角覆盖层 `heroOpen`（同 `wardrobeOpen` 模式）：仅 `uiState==='title'|'select'` 可开。
  - 开：`C` 键（`KEYMAP.hero=['KeyC']`）或标题/选关屏「角色」按钮。
  - 渲染 `renderHeroSelect(tick)`：面板 `(42,24,300,190)`，两张卡，**左侧 knight 右侧 mage**；
    每卡：头像（16×16 放大 3 倍 = 48×48，mage 用 `SPR.mgIdle1`）、角色名、HP（心数）、
    MP（有/无）、四条技能（名 + 键位 + CD + 法力）。当前角色金框 + 「使用中」。
  - 输入 `stepHeroInput()`：←→ 选卡，Enter/Space 确认并 `progress.hero=id; saveProgress`，
    `C/Esc` 关闭；鼠标点卡=选中并确认，点 X 关闭。独占输入，不落到下层菜单。
- 标题按钮：`(328,110,50,18)`「角色」+ C 徽标；底栏文案加 `C HERO`。
- 选关屏按钮：`(252,20,60,13)`「角色」+ C 徽标；底栏文案加 `C 角色`。
- `computeHover` 增加 `titleHero` / `menuHero` / `hero:0|1` / `heroclose`。
- 选角后若当前在选关屏，**下一次 startLevel 生效**；面板里明确写「下一关生效」。

### 3.2 startLevel / boot

- `startLevel` 首行：`game.hero = (progress.hero==='mage') ? 'mage' : 'knight';` **必须在 `loadLevel` 之前**。
- `startLevel` 里 `recomputeEquip()` 的 `maxHp=BAL_PLAYER_HP+eq.hp` 改为
  `p.maxHp = (HEROES[game.hero]||HEROES.knight).hpBase + eq.hp`。
- `boot()`：`game.hero = progress.hero==='mage'?'mage':'knight';` 在 `startLevel`/首帧前；
  `?hero=mage` 调试参数覆盖（非法值忽略）。
- `renderBag`：肖像按 hero 取帧；攻击/生命行不变（伤害仍 `atkBase+equip.atk`）。

### 3.3 渲染

- `heroPoseImg(tick)` 首行：`if(game.hero==='mage') return magePoseImg(tick);`
  - `magePoseImg`：idle1/idle2（40 帧切换）、run[6]、jump/fall、attack（`p.atkT>0||p.atkWind>0`）、
    cast（`p.castT>0`，优先）、dash/dashWind、land squash；按 `p.face<0` 取 `...L` 变体。
    不使用 `getHeroSkin`、不叠装备外观。
- `renderPlayer` 死亡分支：mage 用 `SPR.mgFall`（有 L 变体按朝向），其余同现有。
- `renderSlash`：`if(game.hero==='mage')return;`（法师没有近战弧光）。`renderGhosts` 不动。
- 施法姿态：mage `p.castT>0` 用 `SPR.mgCast`；HUD/特效沿用。
- `renderUlt`：`if(game.hero==='mage'){renderMageUlt();return;}`
  - 0~0.35：紫青压暗 + 玩家脚下魔法阵（双旋转环 + 6 个符文点）。
  - 0.35~0.9：世界正常可见，屏幕上方落 6 道青紫流星（按 `game.meteors` 中 `m.mage` 的世界坐标
    换算到屏幕），落点画 30px 光圈。
  - 0.9~1.2：白闪沿用 `game.flashT`，紫环扩散收尾。
- `renderTitleCover`：`progress.hero==='mage'` 且 `SPR.cover.mageSil` 存在 → 画法师剪影；
  否则原勇者剪影。悬浮位移逻辑不变。

### 3.4 HUD

- 技能槽图标：mage 用 `SPR.mgU/mgI/mgO/mgL`，knight 用 `SPR.skU/skI/skO/skL`；字母 U/I/O/L 不变。
- 槽位 CD 分母改为 `HEROES[hero].skills[slot].cd`（不再硬编码 8/12/20/6）。
- 法力条（仅 mage）：画在血条面板 `(1,16,104,14)` 内右半区：
  `MP` 3×5 字体在 `(62,20)`；槽 `(72,21,28,5)`；填充色 `#48c8f8`，低于技能费用时 `#f87858` 呼吸；
  外框 1px `#3a4468`。**不新增纵向空间**（避免与 Boss 血条 y=29 冲突）。

### 9.1 三个必须解决的实现坑

**① 八向冰锥对同一目标会重复结算。** 贴身时 8 枚全插在一个敌人身上 → 3×8 = 24 伤，比 O 还狠。
出膛时给这一批冰锥打同一个 `novaSeq`，命中时把序号记到 `e.novaSeq` / `game.boss.novaSeq`，
命中循环开头判 `e.novaSeq === s.novaSeq` 就跳过。同一敌人对同一次新星只吃 1 次伤害，但**八枚都还在飞**（视觉保留）。

**② 冻结不能逐条改 AI 分支。** 敌人有 9 种类型，逐条置零必漏。
在 ⑨ 敌人循环最前面加 `if (e.freezeT > 0) { ...; continue; }`，语义 = 定身 + 停 AI + 不吃重力（空中被冻就浮在冰里）
+ 不结算接触伤害（可穿过、踩不上）。位置必须在 `e.t += dt` **之前**，否则冰壳里的敌人还在扭。

**③ `continue` 会跳过状态计时。** `flashT`/`jitT` 的衰减在 AI 分支之后（第 4589 行），被 `continue` 跳过
→ 冰壳里的敌人白闪整整 0.8s，实机看就是个白团（截图才发现）。必须在冻结分支里自己补衰减，并把 `kb` 清零
（否则解冻瞬间补一次延迟击退）。

### 11.1 为什么不能复用骑士的部件网格

骑士的 `SPR.look` 是固定锚点的覆盖层：`hat rows0..4 cols4..11`（头盔扣头顶）、
`weapon rows7..15 cols10..15`（剑握右手 y7..15）、`cape rows5..15 cols0..6`（左缘）。

法师的骨架不一样：尖顶帽占满 `rows0..4` 且逐行加宽（`[7,1][6,3][5,5][4,7][2,12]`），
法杖在 `x13` 且有**四种姿态**（竖持 3 / 高举 0 / 横刺 7 / 低垂 13），
`dy`/`lean`/`sway` 还会整体位移。照搬的结果是「尖帽上扣一顶头盔」「一手持杖一手持剑」，
而且每种姿态都得配一套偏移量。

改为在 `_mgDraw(g, o, PL, E)` 里按档位**改画法**，`E={w,h,c}` 各取 `-1`(未穿)/`0..2`(档)。

### 11.2 三个视觉上的反直觉结论（都是截图后返工的）

**① 杖头不能靠四角星辉撑大。** 首版在 3×3 菱形外再补四角半透明白，结果 3×3 被填成实心方块，
3× 下就是一块亮豆腐，比原版 2×2 更不像宝石。改回「四角留空、四臂用宝珠色、心用纯白」的菱形。

**② 披风外缘不能用金色。** 披风只有 2~5px 宽，1px 金边占掉 20%~50%，在 3× 下像一根金属棍插在背后，
不像披风的边。改成「同色系亮一阶」作外缘，金色只留给档3的**肩线**（一行 5px，是档3的主要辨识点）。

**③ 外缘与内收边不能用同一个亮色。** 两者同亮时整块披风变成一条白边，档位色反而看不见。
三色分工固定：`b` 布面 / `e` 外缘受光 / `s` 内衬暗收边（只有行宽 >2 时才画收边，1~2px 宽时整条只剩暗）。

### 11.4 顺手修掉的两个骑士 bug

**`lookEq()` 把稀有度当数组下标用。** 原写法 `SPR.look.weapon[w.r]`，而 `SPR.look.*` 只有 3 档（`0/1/2`）、
`w.r` 是稀有度 `0..4`。后果：`r=2`（蓝）取到第 3 档（金星辉）、`r=3`（紫）/`r=4`（金）取到 `undefined` →
**紫装和金装在骑士身上完全没有外观**。改为先 `lookTier(r)` 再查表。

**键名不一致。** `lookEq()` 返回 `{weapon,hat,cape}`，法师侧首版按 `{w,h,c}` 读 → 静默全落 `-1`，
表现为「三件全穿、属性生效、外观零变化」（像素 diff = 0，截图看不出来，靠 diff 才定位）。
