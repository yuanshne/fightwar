# v4 谜题神龛：数织（Nonogram）+ 数独（Sudoku）施工工单

> 需求：把数独和数织作为游戏的一个小部分加入。设计：主 agent（省额度，跳过设计师环节）。
> 施工：Flash 四队，文件所有权互斥，各自过门禁。前置：v3 已合入（七关+Boss+技能）。

## 玩法设计（一句话）

每关（L1~L6）藏一座「谜题神龛」新实体 'Q'：走近按 ↑/回车 打开谜题覆盖层（世界暂停），
解开得 1 颗宝石(+5 金币)；解开的神龛点亮并把谜底像素画展示在神龛上方。L7 无神龛。
分工：**奇数关=数织，偶数关=数独**，难度递进。

- 数织（L1 5×5 / L3 7×7 / L5 10×10）：谜底是主题像素画（草丛→蝙蝠→Boss 脸），行/列线索
  自动从画稿推导；操作：方向键移动光标、J 填格、K 叉格、R 清空、Esc 退出（进度保留在
  内存，重进关卡重置）；完成时自动校验：错格闪红 1s，全对→胜利。
- 数独（L2 4×4 块2×2 / L4 6×6 块2×3 / L6 9×9 块3×3）：预置题面（手工设计、唯一解）；
  操作：方向键移动、数字键填入、0/Backspace 清除、R 清空重来、Esc 退出；同格再按同数字
  也可清除；冲突格实时高亮（同行/列/块重复）；完成自动校验。
- 通用：覆盖层期间 `game.puzzleActive=true`（updateWorld 直接 return，同 paused 语义但不改
  paused 字段）；完成→烟花粒子+音效 'puzzle'+'gem'；`pq_progress.puzzles={"1":true,...}`
  持久化；已解神龛再次打开可查看谜底（只读模式）。

## 数据契约（新增到 levels.js，关卡数据模块 owns 游戏内容）

```
const PUZZLES = {
  1:{type:'nono', size:5,  pic:['.##.',...]}          // 字符画稿，'#'=实心 → 行列线索由引擎/ui推导
  2:{type:'sudoku', size:4, givens:[[1,0,0,2],[0,...]], sol:[[...]]}  // 0=空
  3:{type:'nono', size:7,  pic:[...]}
  4:{type:'sudoku', size:6, givens:[...], sol:[...]}
  5:{type:'nono', size:10, pic:[...]}                 // 10x10=Boss脸,画稿可复用 art 像素思路但独立定义
  6:{type:'sudoku', size:9, givens:[...], sol:[...]}  // 经典数独,挖空约 40 格
};
```
数织谜底要求：5×5=草丛/花、7×7=蝙蝠或史莱姆、10×10=Boss 脸（要有辨识度）。
数独要求：唯一解（sol 提供完整解；givens 是 sol 的挖空子集）；4×4 挖 8 格、6×6 挖 16 格、
9×9 挖 40 格左右。

## 四队工单

### 引擎队（engine.js）——门禁: node tools/gate.js engine
1. Level 解析新增 'Q'：实体提取为 `shrines:[{x,y,w:16,h:24,idx}]`（idx=关卡号，配 PUZZLES），
   网格换 '.'。
2. `game.puzzleActive=false` 新字段；updateWorld 顶部 `if(game.puzzleActive) return;`（在
   paused 判断之后）。玩家物理/敌人/计时全部冻结（同暂停语义）。
3. 每步计算 `game.puzzleNear`：玩家矩形与神龛（含 8px 外扩）重叠时=该神龛 idx，否则 -1
   （ui 据此显示"↑解谜"提示并处理开键）。
4. 新导出 `function puzzleSolved(idx)`：标记 game.solvedPuzzles[idx]=true、game.coins+=5、
   sfxQueue push 'puzzle'+'gem'、玩家位置上方出烟花粒子（约 24 粒金色）；若 idx 对应关卡
   有未拾取宝石实体不涉及（奖励直接走计数）。`game.solvedPuzzles={}` 在 loadLevel 重置；
   ui 负责从 localStorage 注入已解状态。
5. 冒烟硬约束：'Q' 提取与 puzzleNear 计算不得让七关空转有任何副作用。

### 界面队（ui.js + gate.js）——门禁: node --check ui.js + node tools/gate.js engine
1. 键位：KEYMAP.puzzleOpen=['ArrowUp','KeyW','Enter']（仅 play 态且 puzzleNear>=0 时消费）、
   覆盖层内方向/J/K/R/Esc/数字键。注意与跳跃键冲突：puzzleNear 时优先开龛不跳
   （puzzleNear>=0 时 jumpHit 桥接置 0）。
2. 覆盖层状态机 `puzzle={open,idx,type,size,grid,cur:{x,y},err:0,done}`：渲染半透明黑底+
   木框+题目（数织=左侧/顶部线索+网格；数独=粗细分隔线+给定格灰底+冲突红字）；光标白色
   描边方块；底部操作提示（drawCNText 小字）。
3. 完成校验：数织 grid 与 PUZZLES[idx].pic 全等；数独 grid 与 sol 全等。错误→err=1s 计时
   闪烁；正确→调 puzzleSolved(idx)+本地 solved 持久化+2s 后自动关层。
4. 世界渲染：神龛 sprite（未解=暗色石碑+问号、已解=点亮+顶部展示谜底缩略图：数织画原样、
   数独画一个金色"完"字印章风格）；puzzleNear 时头顶浮动 "↑ 解谜" drawCNText 提示。
5. HUD：已解神龛数/6 小图标显示在金币旁（可选，超时则砍）。
6. localStorage 注入：startLevel 时 game.solvedPuzzles=progress.puzzles||{}。

### 美术队（art.js）——门禁: node tools/gate.js art
1. SPR.shrineOff/shrineOn（16×24 石碑像素画：暗青石+裂纹 vs 点亮+金纹+顶部星光 2 帧闪烁）。
2. SPR.puzzleUI 素材：木框四角/边条（可拼接）、网格光标框、数织叉格标记（8×8 内部画）。
3. 谜底缩略图渲染不需要新素材（ui 直接按画稿/印章画色块），但提供 THEME 无关的金色印章
   色 #f8d048 常量即可。
4. 全部手绘字符网格；导出符号仍限契约 7 个（新精灵挂进 SPR）。

### 关卡队（levels.js）——门禁: node tools/gate.js levels
1. PUZZLES 数据（见上契约；数独三题给唯一解完整题面——建议从已知合法终盘挖孔并自检：
   node 脚本跑一遍解唯一性或人工确保 givens⊂sol 且 sol 合法）。
2. 六关各放 1 个 'Q'：位置在主路径旁的安全高地（不堵路、脚下有支撑、远离即死物），
   检查点附近优先；L7 不放。
3. validateLevels 适配：'Q' 加入实体字符表（不入 SOLIDISH/STAND）；断言 L1~L6 各恰 1 个 'Q'、
   'Q' 下方 2 格内有支撑。

## 红线
不改既有键位语义；不加新全局导出（engine 的 puzzleSolved 除外，写进 CONTRACT 附记）；
各队完成各自门禁并自查后交付；越界=失败。
