# Pixel Quest v2 优化任务书（玩家反馈驱动）

来源：玩家实测反馈「跳跃有 bug、反馈不及时；可交互部分太少；角色太丑」+ 参考《闪翼双星》
（可爱灵动角色 / 攻击+闪避战斗 / 快节奏动作手感）。基线：v1 已全部门禁+浏览器实测通过。

## P0 · 跳跃输入丢失 bug（已定位，须验证+修复）

**根因（主 agent 代码审查结论，测试员须独立验证）**：`ui.js` 的 `clearPressed()` 在每个
rAF 渲染帧末尾无条件清空 pressed 标志，但物理步进 `step()` 是固定 60fps 累加器——高刷新率
屏幕（≥120Hz）上大量渲染帧内累加器不足 1/60s、**零步进**，按键信号未被任何 step 消费即被
清除 → 跳跃/攻击输入随机被吞，表现为"反馈不及时"。

**修复规格（引擎工程师执行）**：pressed 只在**至少消费了一个 step 之后**清空——把
`clearPressed()` 从 rAF 末尾移入 `while(acc>=1/60)` 循环之后且以 `ran>=1` 为条件；或改为
keydown 事件直接置位 `game.input.jumpHit` 等引擎输入锁存。两法选一，保证信号不丢不重。

**验收（测试员）**：注入 50 次 keydown(ArrowUp)，逐帧轮询 `game.player.vy`，全部在 ≤2 帧
内出现 vy<0，零丢失；60Hz 与 120Hz（`page.evaluate` 改造 rAF 时间步模拟）均须通过。

**主 agent 实测证据（2026-10-24，tools/latency.py）**：
- v1 @60Hz 无头：30 试 0 丢失，中位 9ms；
- v1 @144Hz 模拟（rAF 强制 7ms，物理仍锁 60fps）：**30 试丢 15（50%）**——根因坐实。
- 修复后回归标准：144Hz 模拟下丢失率必须为 **0%**。

## P1 · 手感调优（引擎工程师，engine.js）

- coyote 0.09→**0.12s**，buffer 0.11→**0.18s**；起跳/落地粒子加强；落地 squash（渲染层
  y 压缩 0.15s）；死亡震屏 6→8、击杀震屏新增 3。
- **攻击**（J/X 键）：冷却 0.35s；身前 18×14 判定框存在 0.12s；命中敌人→敌死+玩家不弹跳+
  **hit-stop 全局冻结 0.06s**；命中 'B' 砖→砖碎；音效事件 'slash'。
- **冲刺**（K/Shift）：冷却 0.8s，0.18s 内 vx=±260 且不受摩擦衰减、重力减半，冲刺尾迹
  （残影：ui 按 0.04s 间隔记录玩家姿态快照绘制半透明剪影，共 4 帧）；音效 'dash'。
- **连击**：击杀/碎砖 2s 窗口内累计 `game.combo`（n≥2 显示），断档清零；音效 'combo'。
- 敌人被攻击击杀与踩踏等价（史莱姆/蝙蝠均可）；炮弹可被斩碎（音效 'break'）。

## P2 · 角色重画（画师，art.js）

《闪翼双星》风格：**可爱+灵动+飘逸**。规格：
- 主角升级 16×16「星之勇者」：亮蓝白主色+橙色飘带围巾+胸前星徽+大眼睛；帧：idle2（眨眼+
  围巾飘）、run6（明显跑动姿态+围巾拖尾）、jump/fall（围巾上扬/下坠）、attack（挥臂前倾）、
  dash（流线前倾）、squash（落地压扁）各 1；全部含左向翻转版。
- 命中框仍 10×14 不变（渲染可溢出）；`SPR` 键名在 v1 基础上新增：heroAttack/heroAttackL/
  heroDash/heroDashL/heroSquash，heroRun 扩到 6 帧（ui 渲染按 `p.animT*12%6` 取帧）。
- 特效素材：slashArc[3]（挥击弧光 18×14，白→蓝渐隐）、breakBrick 瓦片（裂纹木箱 16×16）、
  combo 弹字由 ui 用 drawPixelText 放大绘制（无需新素材）。
- 敌人小翻新：史莱姆加高光+表情帧、蝙蝠翅膀 3 帧。所有新像素数据手绘字符网格，禁止外部图片。
